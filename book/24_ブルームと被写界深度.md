# ブルームと被写界深度

## この章の読み方

### この章を読む前に必要な知識

23章のポストプロセスと03章のカメラの見え方を知っていると読みやすくなります。深度から距離を求める計算規則は41章で参照できます。

### 初回に読む範囲

BloomPassとDofPassの役割、最小実装、主要パラメーターを先に読んでください。

### 必要になったときに読む範囲

深度デバッグ、フォーカスマスク、画像ピラミッド、HDR（High Dynamic Range：広い輝度範囲）処理は見え方を調整するときに参照してください。

### この章を終えた時点でできること

明るい部分のにじみと焦点距離によるぼかしを設定し、色と深度の問題を切り分けられます。

## BloomPassの実装と活用

`BloomPass`は、発光体や強い反射の周囲へ光のにじみを加え、明るさの差を画面上で強調したいときに使います。
色テクスチャだけで完結するため、オフスクリーン描画と全画面合成の基本を、深度復元や追加マスクなしで学べる利点があります。

### 役割と仕組み

`BloomPass` は、シーン内の輝度が高い部分のみを抽出し、それをぼかして元のシーンに加算することで、光がにじみ出すような視覚効果を演出します。
カラー情報のみを利用して動作するため、ポストプロセスの基本を理解するのに最適なコンポーネントです。

内部では `sceneTarget`（元のシーン）、`extractTarget`（輝度抽出）、`extractHeatTarget`（しきい値処理後）、および `SeparableBlurPass` が管理するぼかし用ターゲットを使用します。
利用者は `new BloomPass(gpu, options)` でインスタンス化し、`await bloom.ready` で準備完了を待機した後、前述の基本サイクルに従って制御します。

### 実装例

次の例は、シーンをブルーム用ターゲットへ描き、抽出とぼかしを実行してキャンバスへ合成する最小の接続を示します。
リソースを作る段階と毎フレームの処理を分けて読むと、初期化漏れとパス順序の誤りを区別できます。

```js
import BloomPass from "./webg/BloomPass.js";

const bloom = new BloomPass(app.getGPU(), {
  width: app.screen.getWidth(),
  height: app.screen.getHeight(),
  threshold: 0.68,
  extractIntensity: 1.0,
  softKnee: 0.35,
  bloomStrength: 1.15,
  exposure: 1.0,
  toneMapMode: 0,
  blurScale: 1.0,
  blurIterations: 2,
  blurRadius: 1.0
});
await bloom.ready;

app.start({
  onUpdate: ({ screen }) => {
    bloom.resizeToScreen(screen);
  },
  onBeforeDraw: () => {
    bloom.beginScene(app.screen, app.clearColor);
    app.space.draw(app.eye);
  },
  onAfterDraw3d: () => {
    bloom.render(app.screen, {
      source: bloom.getSceneTarget(),
      clearColor: app.clearColor
    });
    app.screen.clearDepthBuffer();
  }
});
```

### デバッグビューによる調整

ポストプロセスの調整において、中間結果を可視化することは極めて重要です。
`BloomPass` は内部ターゲットへのアクセス用ゲッターを提供しているため、`FullscreenPass` を利用して現在の状態を確認できます。

```js
import FullscreenPass from "./webg/FullscreenPass.js";

const debugPass = new FullscreenPass(app.getGPU(), {
  targetFormat: app.getGPU().format
});
await debugPass.init();

let bloomView = "composite";

app.start({
  onUpdate: ({ screen }) => {
    bloom.resizeToScreen(screen);
  },
  onBeforeDraw: () => {
    bloom.beginScene(app.screen, app.clearColor);
    app.space.draw(app.eye);
  },
  onAfterDraw3d: () => {
    bloom.render(app.screen, {
      source: bloom.getSceneTarget(),
      clearColor: app.clearColor
    });

    if (bloomView !== "composite") {
      const debugSource = bloomView === "scene"
        ? bloom.getSceneTarget()
        : bloomView === "extract"
          ? bloom.getExtractTarget()
          : bloomView === "extractHeat"
            ? bloom.getExtractHeatTarget()
            : bloomView === "blurA"
              ? bloom.getBlurTargetA()
              : bloom.getBlurTargetB();

      app.screen.beginPresentPass({
        clearColor: app.clearColor,
        colorLoadOp: "clear"
      });
      debugPass.draw(debugSource);
    }

    app.screen.clearDepthBuffer();
  }
});
```

特に `extract`（抽出）と `extractHeat`（熱量抽出）を比較することで、しきい値（threshold）や `softKnee` がどのように効いているかを視覚的に把握でき、効率的なパラメータ調整が可能になります。

ここで使う`BloomPass`は、標準Forward描画で作った表示用のシーン色へレンダーパスを重ねる実装です。PBR統合レンダリングでは、Tone Mapping後の明るさではなく、Tone Mapping前の線形HDR放射輝度から高輝度領域を抽出する必要があります。そのため、34〜36章の`ComputeBloomPass`または31〜33章の`ComputeEffectPipeline`を使用します。

## DofPassの実装と活用

`DofPass`は、焦点を合わせたい距離だけを鮮明に残し、手前と奥をぼかして視線誘導と奥行きを表すために使います。
シーン色に加えて、そのシーンを描いた深度と同一フレームの証明が必要になるため、深度依存ポストプロセスの基本的な前提条件も確認できます。

### 役割と仕組み

`DofPass` は、シーンのカラー情報に加えて「深度情報」を参照し、合焦面（フォーカス面）だけを鮮明に残し、それ以外をぼかすエフェクトです。
ブルームとの最大の違いは、後段の処理で深度テクスチャを利用する点にあります。

現在の `DofPass` は、多段階ぼかしを使います。
1枚の強いぼかし画像へ急に切り替えず、`small`、`medium`、`large` の3段階を作ります。
深度差に応じて、`scene -> small -> medium -> large` の順に合成します。
これにより、合焦面を外れた直後に強いぼかしへ飛ぶ見え方を抑えられます。

内部では、`sceneTarget`、`depthDebugTarget`、`focusDebugTarget`、`stageDebugTarget` と、3段階のぼかし用ターゲットを保持します。
距離復元に使う`near`と`far`は、同じ描画フレームの`renderFrameToken`から解決した内部カメラフレームで共有します。

合焦距離は、DoF passへ固定値を渡す方法と、`EyeRig`が解決した現在のカメラ距離を使う方法を選べます。
カメラ操作と実世界のレンズを対応させる場合は、`EyeRig.focus`で合焦対象を指定し、`focusSource: "camera"`で同じフレームの`CameraFrame.focusDistance`を読む構成にします。
このとき`EyeRig`は合焦対象を決め、`DofPass`はその距離の周囲をどの程度ぼかすかを決めます。

`focusRange` は、最大ぼかしへ到達するまでの全体距離ではなく、1つのぼかし段階が進む距離幅として扱います。
焦点からの距離差が `focusRange` の1倍までで `scene -> small`、2倍までで `small -> medium`、3倍までで `medium -> large` へ移ります。
この考え方にしておくと、焦点面から外れた直後の見え方と`stageMask`の色分けを確認できます。Compute版ではcoverageとCoCを分けて保持することで、焦点外geometry内部に鮮明なscene colorが残る問題を避けます。

### 実装例

次の例では、同じオフスクリーンシーン、深度、`renderFrameToken`を描画とDoFへ渡します。
値を個別に再構成せず同じトークンで結ぶことで、カメラが動いても合焦距離と描画深度を同じフレームとして扱えます。

```js
import DofPass from "./webg/DofPass.js";

const orbit = app.createOrbitEyeRig({
  target: [0.0, 1.5, 0.0],
  distance: 18.0,
  focus: {
    enabled: true,
    mode: "camera-target"
  }
});

const dof = new DofPass(app.getGPU(), {
  width: app.screen.getWidth(),
  height: app.screen.getHeight(),
  // WebgAppが作るCameraFrameのfocusDistanceを毎フレーム使う
  focusSource: "camera",
  focusRange: 6.0,
  maxBlurMix: 1.0,
  blurScale: 0.5,
  stageBlurIterations: {
    small: 1,
    medium: 2,
    large: 4
  },
  stagedStageCount: 3,
  blurRadius: 2.4
});
await dof.ready;

app.start({
  onUpdate: ({ screen }) => {
    dof.resizeToScreen(screen);
  },
  onBeforeDraw: ({ renderFrameToken }) => {
    dof.beginScene(app.screen, app.clearColor, { renderFrameToken });
    app.space.draw(renderFrameToken);
  },
  onAfterDraw3d: ({ renderFrameToken }) => {
    dof.render(app.screen, {
      renderFrameToken,
      clearColor: app.clearColor
    });
    app.screen.clearDepthBuffer();
  }
});
```

`focusSource: "camera"`を選ぶと、`beginScene()`と`render()`が同じ`renderFrameToken`から`CameraFrame`を解決し、その`focusDistance`をuniformへ反映します。
Orbitをズームするとカメラと注視点の距離が変わるため、次のフレームではDoFの合焦面も同じ対象へ追従します。
`focusSource`の既定値は`"explicit"`で、低レベルの`DofPass`へ`focusDistance`を直接渡す従来の使い方も維持できます。

動くNodeへ焦点を合わせる場合は、EyeRig側で次のように指定します。

```js
app.createOrbitEyeRig({
  target: [0.0, 1.5, 0.0],
  distance: 18.0,
  focus: {
    enabled: true,
    mode: "node",
    targetNode: ballNode,
    targetOffset: [0.0, 0.0, 0.0]
  }
});
```

`WebgApp`はEyeRigの更新後に現在のカメラ姿勢でNodeのワールド位置を視点空間へ変換し、その正の`-Z`距離を`CameraFrame.focusDistance`へ保存します。
したがって、`WebgApp`がNode位置から毎フレームの`focusDistance`を更新します。アプリケーション側は焦点対象NodeをEyeRigへ渡します。
`focusRange`、`blurRadius`、`stageBlurIterations`はDoF passの見え方を決める値として、EyeRigから分離して管理します。

`DofPass`を`WebgApp`と独立して使う場合は、`focusSource: "explicit"`で合焦距離を直接設定します。
独自に作った`EyeRig`と接続する場合は、同じ描画フレームの`CameraFrame`を使って`eyeRig.getFocusDistance(cameraFrame)`を呼び、`dof.setFocusDistance(...)`を`beginScene()`の前に実行します。
DoF passが全体カメラやNodeを暗黙に探すことはなく、入力元を明示することで別フレームの深度と合焦距離が混ざる状態を検出できます。

DoFを導入する際、最も注意すべき点は `sceneTarget` がカラー情報だけでなく、サンプリング可能なカメラ用Reverse-Z深度を保持していることです。
シーン開始、`Space.draw()`、合成へ同じ`renderFrameToken`を渡すと、`DofPass`は同じカメラフレームで作られた深度であることをオブジェクト同一性で検証できます。
前フレームのトークンや別の`WebgApp`のトークンは拒否されます。
`focusRange` は1段階分の距離幅として扱います。
`blurIterations` は3段階へ同じ反復回数を指定し、`stageBlurIterations`は段階ごとに反復回数を変えます。
小さいぼかしは画面解像度に近いターゲットで実行されるため、`small: 1`、`medium: 2`、`large: 4`のように必要な段階へだけ反復を割り当てる方が扱いやすくなります。

### 深度デバッグとフォーカスマスク

DoFの調整は、深度条件と合焦範囲が視覚的に分からないと困難です。
そのため、内部的に深度、合焦範囲（focusMask）、段階選択（stageMask）をカラーターゲットへ出力するヘルパーを活用します。
`stageMask` では、現在の画素がシーン、small、medium、largeのどの段階として合成されるかを確認できます。

```js
import FullscreenPass from "./webg/FullscreenPass.js";

const debugPass = new FullscreenPass(app.getGPU(), {
  targetFormat: app.getGPU().format
});
await debugPass.init();

let dofView = "composite";

app.start({
  onUpdate: ({ screen }) => {
    dof.resizeToScreen(screen);
  },
  onBeforeDraw: ({ renderFrameToken }) => {
    dof.beginScene(app.screen, app.clearColor, { renderFrameToken });
    app.space.draw(renderFrameToken);
  },
  onAfterDraw3d: ({ renderFrameToken }) => {
    dof.render(app.screen, {
      renderFrameToken,
      clearColor: app.clearColor
    });

    if (dofView !== "composite") {
      const debugSource = dofView === "scene"
        ? dof.getSceneTarget()
        : dofView === "depth"
          ? dof.getDepthDebugTarget()
          : dofView === "focusMask"
            ? dof.getFocusDebugTarget()
            : dofView === "stageMask"
              ? dof.getStageDebugTarget()
              : dofView === "blurSmall"
                ? dof.getSmallBlurTarget()
                : dofView === "blurMedium"
                  ? dof.getMediumBlurTarget()
                  : dofView === "blurLarge"
                    ? dof.getLargeBlurTarget()
                    : dof.getSceneTarget();

      app.screen.beginPresentPass({
        clearColor: app.clearColor,
        colorLoadOp: "clear"
      });
      debugPass.draw(debugSource);
    }

    app.screen.clearDepthBuffer();
  }
});
```

`depth` と `focusMask` を切り替えて確認することで、`focusDistance`（合焦距離）が同じ`renderFrameToken`から取得したカメラの投影設定と整合しているか、どの領域がシャープに維持されているかを即座に判断できます。
さらに `stageMask` と `blurSmall`、`blurMedium`、`blurLarge` を確認すると、ぼかし画像そのものが破綻しているのか、深度に応じた段階選択が意図と違うのかを切り分けられます。

レンダーシェーダー版DoFは、色だけの後処理から一歩進み、前段の深度とカメラ情報を後段へ引き継ぐ例です。この入力関係は、G-buffer深度から位置を復元する遅延レンダリングを理解する助けになります。PBR統合レンダリングでは、`ComputeDofPass`が線形HDRシーンと同じ`cameraFrame`を使い、Tone Mapping前にDoFを処理します。

## まとめ

ブルームは明るさを基準に画像を抽出して広げ、被写界深度は深度とカメラ情報から焦点距離に応じたぼかしを選びます。色だけを扱う効果と、深度やカメラフレームを必要とする効果を分けると、入力不足による表示異常を調べやすくなります。
透明表面、曇りガラス、ビネットなどの仕上げは、続く25章で確認します。
