# 物理エンジンの詳細設計

## この章の読み方

### この章を読む前に必要な知識

27章の利用方法と03章の座標・回転を知っていると読みやすくなります。

### 初回に読む範囲

OBB（Oriented Bounding Box：向き付き境界ボックス）、SAT（Separating Axis Theorem：分離軸定理）、慣性テンソル、接触点、回転コンタクトソルバーの役割を先に読んでください。

### 必要になったときに読む範囲

支持接触、接触点構成、角速度、sleep判定は物理挙動を調べるときに参照してください。

### この章を終えた時点でできること

PhysicsSpace内部の形状判定と接触解決が安定性へ与える影響を追跡できます。

## 物理エンジンの内部動作原理

内部動作は、回転した箱の判定、接触点の速度、姿勢更新、sleep判定を変更する場合や、見た目に対して押し戻し方向が不自然な問題を調べる場合に理解します。
広域判定からソルバーまでの処理段階を分けて読むことで、判定漏れと応答の不安定さを同じパラメーターで直そうとせずに済みます。

### 回転を伴うボックス判定（OBB）の実現

物理エンジンの実装において、ボックスを「軸に平行な箱（AABB）」として扱うか、「回転した箱（OBB）」として扱うかは非常に重要な分岐点となります。
AABBのみの実装は軽量ですが、見た目のボックスが回転しているにもかかわらず当たり判定がワールド軸に固定されていると、接触位置や押し戻し方向が直感とずれてしまいます。

そこで `webg` では、`BoxCollider` をボディのクォータニオン姿勢を反映したOBB（Oriented Bounding Box）として扱う設計を採用しています。
一方で、毎フレームすべてのボックス同士に重い判定を行うと負荷が高くなるため、ブロードフェーズ（広域判定）では外接AABBを用いて候補を絞り込む最適化を行っています。

具体的な処理は `webg/BoxCollider.js` の `getWorldInfo()` と `getAabb()` で実装されています。

```js
// webg/BoxCollider.js
getWorldInfo(position, quat = null) {
  return {
    center: this.getWorldPosition(position, quat),
    half: this.getHalfExtents(),
    axes: this._getOrientationAxes(quat)
  };
}

getAabb(position, quat = null) {
  const info = this.getWorldInfo(position, quat);
  const extent = [0.0, 0.0, 0.0];
  for (let worldAxis = 0; worldAxis < 3; worldAxis++) {
    extent[worldAxis] =
      Math.abs(info.axes[0][worldAxis]) * info.half[0] +
      Math.abs(info.axes[1][worldAxis]) * info.half[1] +
      Math.abs(info.axes[2][worldAxis]) * info.half[2];
  }
  return {
    min: [info.center[0] - extent[0], info.center[1] - extent[1],
          info.center[2] - extent[2]],
    max: [info.center[0] + extent[0], info.center[1] + extent[1],
          info.center[2] + extent[2]]
  };
}
```

`getWorldInfo()` は、現在のボディの位置と向きに基づいて、OBBの中心、半サイズ、およびワールド空間での方向軸（axes）を算出します。
`getAabb()` では、これらの情報を基にOBBを完全に包み込む最小のワールドAABBを算出しています。
この手法により、ブロードフェーズでは高速なAABB比較で候補を絞り込み、候補に残ったペアのみを詳細なOBB判定（ナローフェーズ）に回すことができます。

### OBB同士の接触判定（SAT）

候補に残ったボックス同士の接触は、SAT（分離軸定理：Separating Axis Theorem）を用いて判定します。
これは、「ある軸に投影したときに隙間があれば接触していない」という原理に基づいています。
判定に使用する軸は、各OBBの3本の方向軸と、それらの外積から得られる9本の軸、計15本です。

`BoxCollider.js`は`getWorldInfo()`と`getVertices()`でbodyの姿勢からOBBの中心、半サイズ、3本のworld軸、8頂点を作ります。Box/Boxの接触pairは`PhysicsContactDispatcher.js`がCPUによるBox接触へ渡し、15軸SATとsupport featureの計算は`BoxContact.js`で行います。

次のコードは、15軸を検査する処理の構成を簡略化したものです。
```js
// webg/BoxContact.js の buildBoxContactGeometry() 内部
for (let i = 0; i < 3; i++) {
  if (!testSatAxis(boxA.axes[i])) return null;
  if (!testSatAxis(boxB.axes[i])) return null;
}
for (let i = 0; i < 3; i++) {
  for (let j = 0; j < 3; j++) {
    const axis = [
      boxA.axes[i][1] * boxB.axes[j][2] - boxA.axes[i][2] * boxB.axes[j][1],
      boxA.axes[i][2] * boxB.axes[j][0] - boxA.axes[i][0] * boxB.axes[j][2],
      boxA.axes[i][0] * boxB.axes[j][1] - boxA.axes[i][1] * boxB.axes[j][0]
    ];
    if (!testSatAxis(axis)) return null;
  }
}
```

`testSatAxis()`関数は、指定された軸へ両方のOBBを投影し、その区間が重なっているかを確認します。
すべての軸で重なりがあった場合にのみ「接触している」と判断し、最も重なりが小さい軸を接触法線およびめり込み量の候補として採用します。

CPUによるBox接触は、SATで選んだ最小重なり軸からsupport featureを選び、両側のsupport feature中心を平均した代表接触点を1点へ集約します。面や辺のsupport featureを選び、標準の`PhysicsSpace`ではこの代表点を接触多様体の入力として扱います。
Compute版では、形状とbody種別に応じて接触点数を選びます。`ComputePhysicsShader.js`は、Box同士で一方の逆質量が正、もう一方がゼロの場合に`computeBoxContactManifold()`を使います。これはdynamicなBoxとstatic／kinematicなBoxの組み合わせに対応します。

`ComputeBoxCollider.js`の面接触処理は、接触する面を切り取って接触多角形を一度生成し、そこから最大4点を選びます。solverは得られた点を順に処理します。点数は面の重なりや接触の種類によって変わり、dynamic同士を含むほかの組み合わせは代表点を使います。このため、CPU版の代表点、Compute版の面接触点、読み戻した状態から再計算する接触情報は、それぞれの生成処理を確認して比較します。

固定時間刻みとsolver反復数は接触点数と合わせて調整します。物体の寸法、質量比、摩擦、落下速度をそろえて、接地姿勢、積み重ね、停止までの時間を確認します。

### 慣性テンソルの近似的な扱い

回転を伴う接触応答では、質量だけでなく、物体の形状による回りやすさも考慮する必要があります。
これを表すのが慣性テンソルです。
本来は3×3行列で管理し、姿勢ごとに更新する必要があります。
`webg`では計算負荷を抑えるため、局所軸に沿った対角慣性だけを保持する近似手法を採用しています。

この近似計算は `webg/PhysicsNode.js` で行われています。

```js
// webg/PhysicsNode.js
if (collider?.type === "box" && Array.isArray(collider.size)) {
  const sx = collider.size[0];
  const sy = collider.size[1];
  const sz = collider.size[2];
  return [
    this.mass * (sy * sy + sz * sz) / 12.0,
    this.mass * (sx * sx + sz * sz) / 12.0,
    this.mass * (sx * sx + sy * sy) / 12.0
  ];
}
```

ボックス形状では直方体の慣性モーメントの公式を用い、球体やカプセル形状でもそれぞれの特性に応じた対角成分を算出します。
これにより、「細長い物体は特定の軸まわりには回りやすいが、別の軸には回りにくい」といった基本的な物理特性を表現できます。

### 回転コンタクトソルバーの動作

接触応答では、中心速度だけでなく「接触点における速度」を評価します。
回転している物体では、中心速度がゼロであっても接触点は動いているためです。
`webg` では `v + omega x r`（線形速度 + 角速度 × 半径ベクトル）を接触点速度として計算し、そこにインパルス（衝撃量）を適用します。

`PhysicsSpace.js`には公開stepから呼び出す互換用の委譲メソッドが残っています。実際のCPU式は`CpuPhysicsSolver.js`にあり、接触の共通Impulse計算は`PhysicsContactImpulseSolver.js`へ分離されています。

```js
// webg/CpuPhysicsSolver.js
export function getContactPointVelocity(space, state, r) {
  return space._addVec3(
    state.velocity,
    space._crossVec3(space._degVec3ToRad(state.angularVelocity), r)
  );
}

export function getImpulseDenominator(space, bodyA, stateA, rA, bodyB, stateB,
                                      rB, direction, invMassA, invMassB) {
  const angularA = space._crossVec3(
    space._applyWorldInverseInertia(bodyA, stateA.quat, space._crossVec3(rA, direction)),
    rA
  );
  const angularB = space._crossVec3(
    space._applyWorldInverseInertia(bodyB, stateB.quat, space._crossVec3(rB, direction)),
    rB
  );
  return invMassA + invMassB
    + space._dotVec3(direction, angularA)
    + space._dotVec3(direction, angularB);
}
```

`rA` や `rB` はボディの中心から接触点までのベクトルです。
中心から離れた位置で衝撃を受けたほど、角速度への影響が大きくなります。
`getContactPointVelocity()` では、保存されている角速度を度/secからrad/secへ変換してから `omega x r` を計算します。
ここで度/secのまま外積に渡すと、接触点速度が約57倍ずれてしまいます。

`getImpulseDenominator()` では、線形的な動きやすさと回転による逃げやすさを合算し、有効質量の分母を算出しています。
`_applyWorldInverseInertia()` は、ワールド空間のトルクや角インパルスを、ボディの現在姿勢に応じた局所対角逆慣性へ通します。
戻り値はrad/sec系の角速度変化として扱われます。

実際にインパルスを反映させる処理は以下の通りです。

```js
// webg/CpuPhysicsSolver.js
export function applyContactImpulse(space, body, state, r, impulse, sign, invMass) {
  if (invMass <= 0.0) {
    return;
  }
  state.velocity[0] += impulse[0] * sign * invMass;
  state.velocity[1] += impulse[1] * sign * invMass;
  state.velocity[2] += impulse[2] * sign * invMass;
  if (body?.getFixedRotation?.() === true) {
    return;
  }
  const angularImpulse = space._crossVec3(r, impulse);
  const angularDeltaRad = space._applyWorldInverseInertia(body, state.quat, angularImpulse);
  const angularDeltaDeg = space._radVec3ToDeg(angularDeltaRad);
  state.angularVelocity[0] += angularDeltaDeg[0] * sign;
  state.angularVelocity[1] += angularDeltaDeg[1] * sign;
  state.angularVelocity[2] += angularDeltaDeg[2] * sign;
}
```

この処理により、接触点が中心からずれていれば、線形的な反発だけでなく回転運動も誘発されます。
また、反発インパルスの後に摩擦インパルスも同様の枠組みで適用されるため、接触面に沿った滑りが回転へと変換される挙動も実現しています。

トルク積分でも同じ考え方を使います。
`applyTorque()` で蓄積されたトルクは、`_applyWorldInverseInertia()` によってrad/sec^2系の角加速度へ変換されます。
その後、`_radVec3ToDeg()` で度/sec^2へ戻してから `state.angularVelocity` へ加算します。
つまり、公開状態は度/secに統一し、物理式の内部だけradを使う設計です。

### 支持接触とsleep判定

現行実装では、接触点の位置、法線、penetration、法線・接線方向の累積lambdaを通常のcontact solverで計算し、その結果をsleep判定へ渡します。箱の姿勢と角速度はこの接触解決の結果だけで更新する設計です。

Plane/Boxでは、`PlaneBoxContact.js`がBox頂点から法線方向のactive support点を選びます。support点が重心投影を支えられる場合はbody中心を、そうでない場合はactive点の平均を平面へ投影して、代表接触点を作ります。これにより、1点の頂点接触を無条件に安定支持へ変更せず、支持点の配置を接触計算へ反映できます。

CPUによるBox接触のsleep判定では、Planeのsupport点数、Box同士の支持接触、壁から受ける上向きの摩擦支持を確認します。さらに、線速度と角速度、接触点速度、法線方向速度がしきい値以下である状態を`sleepStepsThreshold`回継続した場合にbodyをsleepさせ、条件から外れた場合はcounterをリセットします。

CPU版の処理経路では、BoxとPlaneだけのSpaceに対して`CpuBoxPhysicsAdapter`が`CpuBoxPhysicsSolver`を接続します。BoxとSphere・Capsuleなどを混在させる場合は`CpuMixedPhysicsPipeline`が同じstate mapへ入れ、Box/BoxとPlane/BoxはCPUによるBox接触、その他の形状pairは一般contact処理へ振り分けます。

全dynamic bodyがsleepした場合は、`PhysicsSpace`が保存済みcontactとcontact eventを使うSpace全体のfast pathへ移ります。活動中bodyが残る場合は通常のstepを続け、一般形状を含む経路では接触island単位のsleep判定、CPUによるBox接触を記録した経路ではbody単位のsleep判定を使います。

## まとめ

物理エンジンの安定性は、形状判定、代表接触点の構成、線形・角速度への力積、有限回転による姿勢更新、スリープ条件が同じ基準で連携することで得られます。Box、Sphere、Capsule、Planeの形状pairを処理段階ごとに分け、支持接触、接触速度、sleep counterを個別に確認することで、振動や停止遅れの原因を追跡できます。
通常のアプリケーションで物理を利用するときは、27章と28章の`PhysicsSpace` APIへ戻り、ここで扱った内部処理を直接組み立てずに利用します。
