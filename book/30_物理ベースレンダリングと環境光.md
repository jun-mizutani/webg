# 物理ベースレンダリングと環境光

本章では、物理ベースレンダリング（PBR）が、マテリアル、光源、環境光、カメラをどのように結び付けて画面の明るさと反射を決めるかを説明します。
マテリアルの金属度と粗さだけでなく、光源の方向、距離、大きさ、高輝度範囲の環境マップ、画像ベース照明、事前積分、露出が最終画像へ与える影響を順に確認します。
設定値を個別に暗記せず、光がどこから来て、表面でどう反射し、どの値として表示されるかを判断できるようにします。

PBRという名前からは、マテリアルを物理的に定義する仕組みが最初に想像されます。実際の見え方は、マテリアルへ表面へ届く光を組み合わせて決まります。同じ金属球でも、小さく強い光源では鋭いハイライトが現れます。広い曇天では、反射が広がり、暗部にも周囲から光が届きます。光源側の情報は、マテリアルと同じくらい重要です。

本章では次の実行例を使います。

- `examples/30_01.html`
  - 金属度と粗さによるマテリアル差を比較します
- `examples/30_02.html`
  - 直接光、環境背景、環境光の拡散反射と鏡面反射の役割を確認します
- `examples/33_01.html`
  - PBR、手続きマテリアル、画面空間反射（Screen Space Reflections：SSR）、透明表現、フォグ、ブルームを統合します

本章はPBRと環境光の入力が持つ意味を整理する章です。これらをG-buffer、SSR、透明描画、画面効果へ接続する実行順は、31〜33章の統合例で確認します。

## この章の読み方

### この章を読む前に必要な知識

07章のマテリアルと、光が表面へ届いて反射する基本概念を知っていると読みやすくなります。

### 初回に読む範囲

base color、metallic、roughness、光源、HDR（High Dynamic Range：広い輝度範囲）、環境光の役割を先に読んでください。

### 必要になったときに読む範囲

GGX（鏡面反射の分布を表す関数）、Fresnel、IBL（Image-Based Lighting：画像ベース照明）の事前積分とキャッシュは、反射や環境光を詳しく調べるときに参照してください。描画処理への接続は31〜33章、格納形式と色空間の詳しい規則は41章で扱います。

### この章を終えた時点でできること

マテリアル、直接光、環境光、HDR（High Dynamic Range：広い輝度範囲）の光量を意味に基づいて設定できます。

## 最初に粗さと金属度を変えてみる

[材質比較の例](examples/30_01.html)を開き、同じ形状で金属度と粗さを変えた表面を見比べます。粗さを小さくすると反射像とハイライトが鋭くなり、大きくすると広がります。金属度を上げると、基本色が鏡面反射の色へ強く作用します。

次のコードは、PBRの描画経路へ配置した`shape`に材質を設定する部分例です。描画パイプラインの作成と表示は32章で説明します。

```js
shape.setMaterial("smooth-shader", {
  color: [0.85, 0.87, 0.90, 1.0],
  specular: 0.5,
  roughness: 0.18,
  metallic: 1.0,
  occlusion: 1.0,
  emissive_factor: [0.0, 0.0, 0.0]
});
```

この例は銀色の金属面を想定しています。まず`roughness`だけを0.18から0.6へ変えて反射の広がりを確認し、次に`metallic`だけを1.0から0.0へ変えて基本色の見え方を確認します。光源とカメラを固定して一つずつ変えると、材質の値が作る違いを判断しやすくなります。

反射が分かりにくい場合は、周囲の明るい領域も確認します。環境光は表面へ届く光であり、金属の反射に映る情報でもあります。以下では、この実行例の見え方を、表面と光の関係から説明します。

## PBRがそろえるもの

PBRは、リアルタイム描画で利用できる情報と時間の範囲で、マテリアル値と光の計算を一貫させる方法です。現実の光の経路をすべて追跡する方式とは異なり、必要な近似を組み合わせて安定した見え方を作ります。

webgの基本PBRは、金属度・粗さ方式（metallic-roughness方式）を採用します。不透明物はPBR G-bufferと遅延照明、透明物はPBR前方描画を使います。どちらも`PbrBrdf.js`のGGX計算を共有します。BRDFは、双方向反射率分布関数（Bidirectional Reflectance Distribution Function）の略で、入射光を視線方向へどの程度反射するかを表します。

現在の主な構成は次のとおりです。

- GGXによる直接光
- 実写HDRを使う遠方環境のIBL
- 基本色、法線、金属度・粗さ、環境遮蔽、発光の各テクスチャ
- glTF 2.0 core PBRマテリアル
- 透明物の共有GGX前方描画
- 相対値と測光単位を選べる光源
- PBR鏡面IBLとSSRの統合
- 画面空間のTransmissionと体積吸収

PBR対応という表現は、実装したマテリアル機能の範囲を示します。クリアコート、布地の光沢、異方性反射、面光源、局所反射プローブ、多層透明などは個別の機能として扱い、対応範囲を具体的に示します。

## 光の流れから考える

表面の色は、マテリアルが定める反射特性と、光源または環境から表面へ届いた光をカメラ方向へ反射した結果で決まります。

![PBRにおける光の流れ](img/fig29_01_pbr_light_transport.jpg)

直接光では、特定の方向から来る光を評価します。画像ベース照明では、表面を囲む全方向から来る光を環境マップから評価します。どちらの場合も、法線、視線方向、光の方向、マテリアルから反射量を求めます。

概念上は次のように分けられます。

```text
最終的な線形HDR色
  = 直接光の拡散反射
  + 直接光の鏡面反射
  + 環境光の拡散反射
  + 環境光の鏡面反射
  + 発光
```

環境遮蔽（Ambient Occlusion：AO）やシャドウは、照明項へ掛ける可視率です。AOは主に環境光が届く割合、シャドウは直接光が届く割合として、対応する項へ適用します。

## 基本色の意味をマテリアルで分ける

基本色（base color）は、非金属と金属で使われ方が異なります。

非金属では、基本色は主に内部へ入った光が拡散して戻る色です。鏡面反射の正面反射率F0は、通常は無色に近い小さな値です。

金属では、光が表面内部で拡散して戻る成分が小さく、基本色を鏡面反射の色として使います。金が金色に見えるのは、波長によって鏡面反射率が異なるためです。この反射の色を基本色へ対応付けます。

webgのF0は、次の考え方で求めます。

```text
dielectric F0 = 0.04 × specular
F0 = mix(dielectric F0, base color, metallic)
```

`metallic: 0`は非金属、`metallic: 1`は金属を表します。中間値は、異なるマテリアルを画素内で平均したテクスチャや境界表現に利用し、単一の純物質では混合領域として解釈します。

## 粗さは微細な面の分布を表す

粗さ（`roughness`）は、目に見えない微細な面が平均法線の周囲へどの程度ばらついているかを表します。この分布が鏡面ハイライトの広がりを決めます。

滑らかな面では、微細な面の向きがそろうため、狭い方向へ強い鏡面反射が出ます。粗い面では向きが広がり、鏡面反射も広い範囲へ分散します。反射の総量と分布を分けて考えることが重要です。

webgの粗さには、0より大きい最小値を設定します。完全な0ではGGXの式が特異な分布になり、数値計算が不安定になるためです。共通の`PBR_MIN_ROUGHNESS`と入力検証で範囲を確認し、範囲外の値は設定エラーとして通知します。

## 線形HDRで光量を保持する

照明計算は、光量の加算と乗算が成立する線形色で行います。表示用のsRGB値を線形色へ戻してから計算し、表示時にsRGBへエンコードします。

HDRは、1.0を超える光量を途中で保持するために使います。太陽、照明器具、鏡面ハイライト、発光面は、白い紙よりはるかに明るくなります。ブルームやトーンマッピングへ明るさの差を渡すため、0から1への圧縮は表示直前に行います。

webgは照明後のシーン色を`rgba16float`で保持します。最後にトーンマッピングを一回だけ行い、ディスプレイへ表示できる範囲へ圧縮してsRGBへ変換します。

PBRの見え方を決める入力は、直接光、画像ベース照明（Image-Based Lighting：IBL）、マテリアル、発光に分けて考えます。ここでは、これらをwebgのAPIへ接続する方法を説明します。

### 1. 方向光

方向光は、非常に遠い太陽などを近似する光です。すべての位置へ同じ方向から届く理想化により、距離減衰を1として扱います。`ComputeEffectPipeline`生成時の`lighting`で色と強度を指定し、トップレベルの`lightDirection`で光が進む方向を指定します。

```js
const pipeline = new ComputeEffectPipeline(gpu, {
  lightDirection: [0.46, -0.82, 0.34],
  lightTarget: [0, -0.7, -4.0],
  lighting: {
    ambient: 0.0,
    directionalColor: [1.0, 0.92, 0.82],
    directionalIntensity: 1.55
  },
  shadow: {
    type: "directional"
  }
});
```

`lightDirection`は「光が進む方向」です。例えば、光が真下へ進む場合は`[0.0, -1.0, 0.0]`を指定します。`lightTarget`は方向光のシャドウマップを配置する中心です。光の方向と、影を計算する領域の中心を分けて指定します。

`shadow.type`はシャドウの方式を選択します。これだけでは影の描画は有効にならないため、`renderScene()`と`pipeline.encode()`の両方で同じ`shadowEnabled: true`を指定します。`lightDistance`、`lightHalfWidth`、`lightHalfHeight`、`lightNear`、`lightFar`は、方向光のシャドウマップが覆う範囲を調整するトップレベルの設定です。

webgコアの初期値と、`examples/33_01.html`で設定している値は異なります。33_01では、立方体の前面へ直接光を当てて鏡面反射をカメラ側へ返しやすくするため、`lightDirection: [0.04, -0.30, -0.95]`、`lightTarget: [5.5, -1.0, -6.8]`を指定しています。

### 方向光に関係するコア初期値

| 項目 | 初期値 |
|---|---:|
| `lightDirection` | `[0.46, -0.82, 0.34]` |
| `lightTarget` | `[0, -0.7, -4.0]` |
| `lightDistance` | `34` |
| `lightHalfWidth` | `19` |
| `lightHalfHeight` | `17` |
| `lightNear` | `1` |
| `lightFar` | `72` |
| `directionalColor` | `[1.0, 1.0, 1.0]` |
| `directionalIntensity` | `1.0` |
| `shadow.type` | `directional` |

### 2. 点光源・円錐光源

点光源は一点から全方向へ光を放つ近似で、円錐光源（`cone`）は一点から特定方向へ光を放つ近似です。どちらも`ComputeEffectPipeline`の既定では0個で、毎フレームの`pipeline.encode()`へ`lights`配列を渡して指定します。局所光源は距離に応じて減衰し、表面までの方向も画素ごとに変わります。

円錐光源の`direction`は光が進む方向、`innerAngle`と`outerAngle`は度単位の角度です。利用者は角度を指定し、コアがそこから内部計算用の`innerCos`と`outerCos`を求めます。

```js
const lights = [
  {
    type: "point",
    position: [-5.0, 3.0, -1.0],
    color: [1.0, 0.9, 0.8],
    radius: 10.0,
    intensity: 2.4
  },
  {
    type: "cone",
    position: [2.0, 5.0, 1.0],
    direction: [0.0, -1.0, -0.2],
    color: [1.0, 0.7, 0.4],
    radius: 15.0,
    intensity: 3.0,
    innerAngle: 25.0,
    outerAngle: 50.0
  }
];

pipeline.encode(commandEncoder, {
  cameraFrame,
  lights
});
```

現在の`examples/33_01.html`では、`LOCAL_LIGHTS`として2個の点光源を定義し、`pipeline.encode()`へ渡しています。点光源と円錐光源は局所照明として使い、シャドウマップを持つ円錐状の主光源は、`shadow.type: "spot"`と`shadow.spot`で別に指定します。

### 3. IBL環境光

`PbrEnvironment`のリソースを`lighting.environment`へ渡します。

```js
lighting: {
  ambient: 0.0,
  environment: pbrEnvironment.getResources(),
  environmentIntensity: 0.70,
  environmentBackground: false
}
```

IBLを使う場合は、環境からの拡散光へ照明を揃えるため、通常は`ambient: 0.0`にします。環境光と固定の明るさを分けて確認するための推奨値です。`examples/33_01.html`でもこの設定を使っています。

### 4. マテリアル側の反射設定

鏡面反射（`specular`）の見え方は、光源に加えて材質側の`specular`と`roughness`で決まります。通常のPBRマテリアルは`Shape.setMaterial()`で指定します。

```js
shape.setMaterial("smooth-shader", {
  specular: 1.0,
  roughness: 0.1,
  metallic: 0.0
});
```

- `specular`を大きくする → 鏡面反射を強くする
- `roughness`を小さくする → 反射を鋭くする
- `metallic`を大きくする → 基本色が鏡面反射へ使われ、拡散反射が減る

発光値`emissive`は自分自身を明るくする値です。他の物体を照らす光源は、直接光源または環境光として別に設定します。

### 共通照明のコア初期値

| 項目 | 初期値 |
|---|---:|
| `lighting.ambient` | `0.035` |
| `lighting.spotColor` | `[1.0, 1.0, 1.0]` |
| `lighting.spotIntensity` | `1.0` |

`spotColor`と`spotIntensity`は、`shadow.type: "spot"`を選んだ主スポット光源へ適用されます。`lights`配列の点光源・円錐光源は、各要素の`color`と`intensity`を使います。

## GGXで鏡面反射を求める

GGX鏡面反射のBRDFは、主に三つの項から構成されます。

### 法線分布は反射方向の広がりを決める

法線分布関数Dは、光と視線の中間方向を向く微細面がどの程度存在するかを表します。粗さが小さいほど分布が狭くなり、ハイライトが鋭くなります。

### 幾何減衰は微細面の隠れを表す

Smith型の幾何減衰Gは、微細面同士が光や視線を遮る割合を近似します。斜めから見る場合や粗い面では、光側とカメラ側の可視率をそれぞれ計算して組み合わせます。

### Fresnelは角度による反射率を表す

Schlick近似のFresnel項Fは、正面反射率F0から、斜め方向で反射が強くなる変化を求めます。水、ガラス、塗装面などの非金属も、斜めから見ると周囲を強く反射します。

`PbrBrdf.js`の直接光計算は、概念上、次の形です。

```wgsl
let f0 = pbrEvaluateF0(baseColor, metallic, dielectricF0);
let fresnel = pbrFresnelSchlick(vDotH, f0);
let distribution = pbrDistributionGgx(nDotH, roughness);
let geometry = pbrGeometrySmith(nDotV, nDotL, roughness);

let specular = distribution * geometry * fresnel
  / max(4.0 * nDotV * nDotL, PBR_EPSILON);
let diffuse = (1.0 - fresnel) * (1.0 - metallic)
  * baseColor / PI;
```

鏡面反射へ配分した光と金属成分を拡散反射から除き、入射光をエネルギー保存に沿って一度ずつ配分します。

## 相対値と測光単位を選ぶ

webgは相対単位系（`relative`）と測光単位系（`photometric`）の二つを明示的に選びます。

相対単位系は、既存シーンで扱いやすい相対強度と有限半径減衰を使います。現実の単位へ対応させず、見た目を基準に値を決める用途です。

測光単位系は、方向光にルクス（lux）、点光源・円錐光源・スポット光源にカンデラ（candela）を使います。距離による照度は逆二乗で減衰します。

```text
照度 ∝ 光度 / 距離²
```

距離が2倍になると、同じ向きの面へ届く照度は1/4になります。距離0では式が発散するため、測光単位系では`minimumDistance`を必須にします。これは計算を適当な値へ丸める代替処理ではなく、有限の大きさを持つ実際の光源へ近づけるための近接限界です。

測光単位系では、トーンマッピングの`exposureEv100`も必要です。光源を物理単位にしても、カメラ露出が未定義なら表示輝度を決められないためです。

## 光源の形と大きさを考える

現実の光源は面積を持ちます。大きさは、表面へ届く光の方向分布、ハイライトの形、影の柔らかさへ影響します。

小さな光源では、届く方向が狭いため、滑らかな面へ小さく鋭いハイライトが現れます。大きな光源では、異なる位置から光が届き、ハイライトは光源の形を反映して広がります。影も、光源の一部が見える領域を持つため半影が広がります。

現在のwebgの点光源、円錐光源、スポット光源、方向光は、リアルタイム計算のために理想化した光源です。面積を持つ光源の全方向を積分する面光源は、別の照明モデルとして扱います。粗さによるハイライトの広がりは表現できますが、長方形照明の形を反射へ直接映す場合は面光源を選びます。

一方、HDR環境マップには、窓、空、照明器具などの見かけの形と大きさを画像として含められます。IBLの鏡面反射では、その高輝度領域がハイライトの形へ影響します。これが、単色の固定環境光とHDR環境を使うIBLの大きな違いです。

## HDR環境マップを光源として使う

高輝度範囲画像は、表示用画像より広い輝度範囲を保持します。Radiance HDR形式では、RGBE形式を使って非常に明るい値を保存できます。

環境マップの各画素は、ある方向から届く放射輝度（radiance）を表します。空の青、地面の反射、窓の白、太陽の高輝度を同じ画像へ保存します。PBRでは、この画像を背景として見せるだけでなく、物体を照らす入力として使います。

通常のJPEGへ白く切り詰めた太陽と、HDRで周囲の数千倍の放射輝度を持つ太陽は、画面表示では似て見える場合があります。しかし、金属面の反射や拡散照明へ積分すると結果が大きく異なります。IBLに使う環境は、照明と反射へ使う光量データです。

Radiance HDR形式の標準原色は、webgの線形sRGBと異なるため、復号処理でRGBEを復号し、IBLの前処理へ渡す段階で原色を明示的に線形sRGBへ変換します。入力の色空間を明示することで、環境光の色を一貫させます。

## IBLで全方向の光を評価する

IBLは、環境画像を全方向の光源として使う方法です。

各画素で環境マップの全方向を直接積分すると、サンプル数が非常に多くなります。そこで、環境とBRDFのうち繰り返し使える部分を事前に積分します。

![IBLの事前積分](img/fig29_02_ibl_precompute.jpg)

webgの`PbrEnvironment`は、主に次のデータをまとめます。

- 放射輝度
  - HDR背景と元の光量環境を表します
- 放射照度
  - 拡散反射用に半球を積分した低周波の照明環境です
- 事前積分済み鏡面環境
  - 粗さごとにGGXで積分した鏡面反射用の環境です
- BRDF参照表（Lookup Table：LUT）
  - 視線角と粗さに依存するBRDF積分を保存します
- サンプラーと鏡面環境のミップ数

## 拡散反射用の放射照度を事前計算する

完全拡散面では、表面法線を中心とする半球から届く光を、入射角の余弦で重み付けして積分します。環境の細かな模様は平均化され、方向ごとの低周波な照明になります。

この結果が放射照度マップ（irradiance map）です。実行時には表面法線の方向から一回参照するだけで、全方向の積分結果を得られます。

放射照度は、球面上の方向、立体角、入射角を考慮した積分です。球面上の光量を積分し、窓のような明るい領域がその方向を向く面へ強く作用する量として求めます。

## 鏡面環境を粗さごとに積分する

鏡面反射は、反射方向の周囲をGGX分布で積分します。滑らかな面は狭い範囲、粗い面は広い範囲の環境を反射します。

webgは粗さごとの結果をミップレベルへ保存します。実行時は`roughness`の値からミップレベルを選び、事前積分済みの鏡面環境テクスチャを参照します。

```wgsl
let maxLod = max(specularMipCount - 1.0, 0.0);
let lod = roughness * maxLod;
let prefiltered = textureSampleLevel(
  prefilteredSpecular,
  environmentSampler,
  reflectionUv,
  lod
).rgb;
```

この処理により、毎画素で多数の環境方向を読む代わりに、事前積分済みの一つのミップを参照できます。

## BRDF参照表で残りの積分を共有する

事前積分済み鏡面環境は、環境側の積分を担当します。フレネル反射と幾何減衰のうち、視線角と粗さで決まる部分は、2次元のBRDF参照表へ保存します。

参照表の軸は、一般に`NdotV`と`roughness`です。マテリアルのF0は実行時に適用するため、同じ参照表を異なる金属色と非金属で共有できます。

```text
鏡面IBL
  = prefiltered environment
    × BRDF参照表から復元した鏡面の重み
```

事前積分は、実行時に共通部分を再計算しないよう、積分を環境側とBRDF側へ分解したものです。環境の放射照度とBRDF参照表を前処理して再利用します。

## 重要度サンプリングで高輝度を捉える

環境マップを均等な方向だけでサンプリングすると、小さく非常に明るい太陽や照明器具を見落とす場合があります。少数サンプルで高輝度領域を一度も選ばなければ、積分結果が暗くなります。

webgのIBL前処理は、Hammersley点列、GGX重要度サンプリング、環境の輝度分布を使う重要度サンプリング、MIS（Multiple Importance Sampling：複数の選び方を組み合わせる方法）を利用します。

Hammersley点列は、乱数だけで方向を選ぶより偏りの少ない点を作ります。GGX重要度サンプリングはBRDFの寄与が大きい方向を選びます。環境重要度サンプリングは明るい画素を選びやすくします。MISは両者の得意な領域を重み付けして統合します。

重要度サンプリングは、同じ積分を寄与の大きい場所へ多くのサンプルを配分して推定する方法です。サンプルの配分を変え、明るい領域の寄与を効率よく評価します。

## 事前積分結果をキャッシュする

高品質なIBLの前処理は、環境の解像度、ミップ数、サンプル数に応じて時間がかかります。生成済みのradiance、irradiance、prefiltered specular、BRDF LUTを保存して再利用すると、起動時は読み込みから開始できます。

webgは生成条件と結果を`.webgpbr`へ保存できます。キャッシュには、入力元ID、生成アルゴリズム、版、解像度、ミップ、サンプル条件を含め、条件の一致を確認して同じ環境として再利用します。

開発中はCPU版とコンピュートシェーダー版を比較し、確定した環境は事前生成済みアセットとして配布できます。実行時は`PbrEnvironment`へ読み込み、不透明物の遅延描画と透明物の前方描画の両方へ同じGPUリソースを渡します。

## 環境光と背景を同じ向きにする

環境マップは、照明と背景表示で同じ回転を使います。背景の窓と物体のハイライトを同じ方向へそろえることで、光源位置が一致します。

`environmentRotationDegrees`は、放射輝度による背景、拡散反射用の放射照度、事前積分済み鏡面環境で同じY軸回転を使います。遅延照明はビュー空間の法線と反射方向をワールド空間へ戻し、環境の回転を適用してテクスチャの方向へ変換します。

環境光を有効にした場合は、`lighting.ambient`を0にすることを推奨します。IBLがすでに環境からの拡散光と鏡面光を含むため、固定環境光を同時に加えると間接光を二重に数えるからです。低水準の描画処理は両方の入力を受け付けますが、`WebgSceneApp`のPBR設定では環境光の有効時に`ambient: 0.0`が必須で、非0を検証で拒否します。

## IBLのエネルギー損失を補償する

通常のGGXは、microfacetで一回だけ反射するsingle-scatteringを評価します。粗い面では、最初のmicrofacet反射が別のmicrofacetへ向かう割合が増えます。そこでの再反射を計算しなければ、特に粗い金属が必要以上に暗くなります。

webgはBRDF参照表から方向別反射率（directional albedo）を復元し、失われた鏡面反射のエネルギーを強度調整したGGX分布で近似的に補償します。

```text
energyCompensation
  = 1 + F0 × (1 / directionalAlbedo - 1)
```

これはリアルタイム向けの多重散乱近似です。補償はIBLの鏡面反射へ適用し、拡散反射用の放射照度、AO、発光、直接光は個別の項として保持します。

## 表面情報を描画処理へ渡す

ここまでの基本色、金属度、粗さ、発光、環境光は、描画処理へ渡す共通の入力です。不透明な表面はG-bufferという画面単位の表面情報へ保存し、後段の照明計算が読みます。透明な表面は背景と重ねる段階で同じ反射モデルを使います。

31章では、照明、反射、透明、画面効果を並べる理由を説明し、32章では接続コードを示します。G-bufferの格納内容、テクスチャのチャンネルと色空間、SSRと環境反射、透明・屈折の内部計算は41章にまとめています。まず材質と光の見え方を確認し、処理を接続する段階で対応する説明へ進めます。

## PBRを調整する順序

最終画像だけを見て多数の値を同時に変えると、マテリアルと光源の原因を切り分けにくくなります。次の順序で調べます。

1. 基本色、金属度、粗さを確認する
2. 法線テクスチャとTBNを確認する
3. 直接光だけで方向、強度、距離減衰を確認する
4. 環境背景の方向と高輝度領域を確認する
5. 放射照度だけを表示して環境光の拡散反射を確認する
6. 鏡面環境のミップとBRDF参照表を確認する
7. PBR照明全体で直接光とIBLを統合する
8. SSRを有効にしてIBL置換を確認する
9. 透明PBRとTransmissionを追加する
10. 最後に露出、トーンマッピング、ブルームを調整する

診断表示を使うと、基本色、法線、粗さ、金属度、環境遮蔽、発光、放射照度、鏡面環境のミップ、BRDF参照表を個別に確認できます。完成画像と各中間値を照合すると、原因を段階的に切り分けられます。

## まとめ

PBRの見え方は、マテリアル、光源、環境、表示変換を組み合わせて決まります。基本色、金属度、粗さ、法線は表面の反射特性を定義します。直接光源は、方向、距離、強度、照射角を定義します。HDR環境マップは、全方向から届く光と高輝度光源の形を定義します。トーンマッピングは、そのHDR結果を表示へ変換します。

IBLでは、拡散反射用の放射照度、粗さ別の事前積分済み鏡面環境、BRDF参照表を事前に計算します。実行時に全方向を積分せず、物理的な意味を保った近似をリアルタイムで利用できます。

webgは、不透明物のPBR遅延描画と透明物のPBR前方描画でGGX計算を共有します。手続きテクスチャ、glTFマテリアル、HDR環境、SSR、Transmissionも同じ線形HDR処理へ接続します。34〜36章では、このPBR情報を画面空間環境遮蔽（Screen Space Ambient Occlusion：SSAO）、シャドウ、SSR、フォグ、被写界深度（Depth of Field：DoF）、ブルームなどの個別パスから利用する方法を説明します。
