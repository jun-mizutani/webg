# パーティクルと軽量エフェクト

衝突時の火花や取得時の光点は、出来事の位置と強さを短時間で伝える演出です。小さな板をカメラへ向ける「ビルボード」を多数使い、発生位置、速度、寿命、色を変えることで作ります。立体モデルを一つずつ動かす処理と比べ、同じ形状を共有しながら多数の短命な表現をまとめて扱えます。

PBRシーンに発光粒子を加えるときは、`WebgSceneApp`へ`ComputeParticleEmitter`を登録します。発生条件はJavaScriptやSceneYAMLに記述し、粒子の初期値生成と移動はGPUが処理します。本章ではこの標準Compute粒子を中心に説明し、CPU側で更新する`ParticleEmitter`の使いどころも整理します。

## この章の読み方

05章のアプリケーション構成と09章のSceneYAMLを理解していると、発生装置の設定と実行時操作を分けて読めます。まず一括発生、連続発生、停止と消去を試し、次に容量とPBRの合成順を確認してください。独自のWGSLで更新式を作る場合は36章の`GpuParticleEmitter`へ進みます。

## 描画経路に合う発生装置を選ぶ

`ComputeParticleEmitter`は、PBR画像へ発光する円形の粒子を加える標準クラスです。GPUで初期位置・速度・寿命を生成し、その状態を描画でも直接読みます。アプリケーションは「どこで、何粒を、どちらへ発生させるか」を決めます。衝突判定やゲームの進行処理から短い呼び出しで利用する場面に適しています。

`ParticleEmitter`は、標準Forward描画でCPU側の状態更新を使うクラスです。手続きテクスチャによる火花、煙、破片、取得演出や、地面に配置する影用ビルボードを扱います。`WebgApp.createParticleEmitter()`へ登録すると、通常のフレーム処理が更新と描画を行います。

`GpuParticleEmitter`は、粒子のデータ配置とCompute・RenderのWGSLを利用側で定義する基盤です。`ComputeParticleEmitter`もこのクラスを継承して、bufferとpipelineの構築を共有しています。独自の運動式や描画方式を組みたいときに選びます。

## PBRシーンへ標準Compute粒子を登録する

初期化済みの`sceneApp`に発生装置を登録します。次の例は、そのシーン内で繰り返し使う火花を作ります。生成は非同期で、完了後に発生要求を受け付けます。

```js
const sparks = await sceneApp.createComputeParticleEmitter({
  label: "collision-sparks",
  preset: "spark",
  capacity: 480,
  seed: 42,
  overflow: "replace-oldest",
  simulation: { gravity: [0, -15, 0], drag: 0.03 },
  appearance: {
    colors: [[8, 3.2, 0.45], [1.2, 5, 8]],
    intensity: 1,
    size: [0.22, 0.44]
  }
}, "collision-sparks");
```

`capacity`は同時に保持する粒子枠の数です。`seed`は乱数系列の出発点を決めます。同じ設定、発生要求の順序、時間刻みで演出を比較するときに役立ちます。`simulation`は重力と速度の減衰率、`appearance`は二つのHDR色、強度、半径の範囲を指定します。色は線形HDRのRGBで、1を超える成分も使えます。二つ目の色は3粒に1粒へ割り当てられます。

プリセットは`spark`、`light`、`fountain`の3種類です。火花、ゆっくり動く光点、上向きの噴出に適した速度分布・寿命・色・半径・重力を用意します。プリセットを出発点として、演出に必要な項目を上書きできます。`fountain`は噴水状の粒子分布を表し、描画には他のプリセットと同じ発光ビルボードを使います。

## 衝突位置から一括発生させる

発生数と発生条件を`emit()`へ渡します。位置はワールド座標、速度はワールド長さ/秒、寿命は秒です。以下は`circular_breaker2`で用いる火花に対応する設定です。

```js
// 衝突位置から上向きに広がる火花を生成する
function emitHitSparks(position) {
  return sparks.emit(32, {
    position,
    velocity: [0, 12, 0],
    velocitySpread: [22, 9, 22],
    lifetime: [0.858, 1.32]
  });
}
```

`velocitySpread`は各軸の速度を基準値の前後へ散らす幅です。`lifetime`は最小寿命と最大寿命を指定します。GPUはこの範囲から各粒子の値を生成します。サンプルではさらに、衝突方向に合わせて水平方向の基準速度を変えています。

方向と開き角で指定する場合は、`direction`、`spreadAngle`、`speed`を使います。角度は中心方向から測った最大角度を度で指定します。`direction`は向きを表し、内部で単位長へ変換します。

```js
sparks.emit(32, {
  position: [0, 1, 0],
  direction: [0, 1, 0],
  spreadAngle: 45,
  speed: [2, 5],
  lifetime: [0.5, 1]
});
```

速度成分と幅による方式、方向と開き角による方式は、発生要求ごとに一方を選びます。範囲の逆転、ゼロの方向ベクトル、未知の項目は設定エラーとして通知されます。

## 連続発生と時間の操作

噴出や環境中の光点は、毎回の発生数よりも秒当たりの発生数で指定すると調整しやすくなります。`startEmission()`は端数を次の更新へ持ち越し、設定した頻度で発生させます。

```js
sparks.startEmission({
  rate: 120,
  position: [0, 0.2, 0],
  direction: [0, 1, 0],
  spreadAngle: 16,
  speed: [6, 8],
  lifetime: [1, 2]
});
```

`stopEmission()`は新しい連続発生を止め、既存粒子は寿命まで動きます。`setPaused(true)`は移動と寿命の時間を止め、カメラに合わせた表示を続けます。停止中に受けた一括発生要求は、`setPaused(false)`による再開まで保留されます。

`clear()`は現在の粒子、保留要求、乱数系列番号、診断カウンターを初期状態へ戻します。連続発生と一時停止の設定は保持します。したがって連続発生中に消去すると、次の更新から粒子が再び生まれます。

`WebgSceneApp`はフレームの時間差とシーンの時間倍率を粒子へ渡します。物理と粒子の一時停止は、それぞれのAPIで操作します。継続した演出にはアプリ生成時に`renderMode: "continuous"`を指定します。`sceneApp.reset()`は登録粒子を消去し、`sceneApp.destroy()`は粒子と描画資源をまとめて解放します。

## 容量と診断から発生量を調整する

必要な粒子枠は、発生頻度と寿命の両方に依存します。衝突ごとの発生数を2倍、寿命を1.5倍にすると、同程度の衝突頻度で保持する粒子数の目安は3倍になります。`circular_breaker2`は衝突ごとに32粒、寿命0.858〜1.32秒、容量480を使います。容量を増やすとGPUの更新対象と描画instance数も増えるため、演出密度と負荷を一緒に確認します。

`overflow: "replace-oldest"`は円環の割当順に古い粒子枠から置き換えます。`overflow: "reject"`は空きの連続した円環領域を探し、要求全体を受理または拒否します。空き領域が細かく分かれている場合も、連続領域の大きさにより判断されます。1回の更新までに保持する発生要求は最大32件です。

`emit()`の返値は`accepted`、`rejected`、`reason`です。容量不足は`particle-capacity`、要求queueの上限は`command-capacity`として確認できます。連続発生の上限超過は`getDiagnostics().rejectedCount`へ加算されます。

`getEstimatedAliveCount()`と診断の`estimatedAliveCount`は、最大寿命からCPUが計算する予約数です。保留要求も含むため、画面上の粒子数より多い場合があります。この推定値により、通常の描画をGPUからの読み戻し待ちにせず、容量調整の情報を表示できます。

## SceneYAMLへ発生設定を保存する

配置と発生条件を作品データとして編集する場合は、シーン直下の`particleEmitters`へ記載します。次は09章のSceneYAMLへ追加する断片です。

```yaml
particleEmitters:
  - id: fountain
    preset: fountain
    capacity: 1024
    seed: 42
    overflow: reject
    emission:
      rate: 120
      position: [-2, 0.2, 0]
      direction: [0, 1, 0]
      spreadAngle: 16
      speed: [6, 8]
      lifetime: [1, 2]
```

`id`はシーン内で一意にします。`emission`を指定すると、初期化時に連続発生が設定されます。一括発生だけを使う場合は、プリセットや容量を定義し、発生のタイミングをJavaScriptへ置きます。

```js
const fountain = sceneApp.getComputeParticleEmitter("fountain");
fountain.stopEmission();
```

設定文書は既存のSceneAssetの保存方法で扱い、YAMLの原文とコメントを保持します。実行中の粒子状態はGPUへ置き、保存する初期設定と分けて管理します。

## PBRの色と深度へ接続する

標準Compute粒子は、透明合成後の線形HDR画像へ加算します。その後にFog、DoF、Bloom、トーンマッピングを適用するため、明るい火花をシーンと同じ露出で表示できます。Bloomは発光のにじみを作り、OFFにすると粒子自体の形と明るさを確認できます。粒子の時間更新はどちらの状態でも継続します。

遮蔽には不透明G-bufferのReverse-Z深度を読み取り専用で使います。床やBoxの奥に入った粒子は隠れ、手前の粒子は表示されます。粒子と床の衝突を演出したい場合は、別途その運動式や衝突処理を設計します。

SSRは粒子を加える前のシーンを参照します。FogとDoFは背景の不透明深度を使います。透明物との前後関係や粒子自身の深度を使う効果が必要な表現では、この適用範囲を踏まえて描画構成を選びます。

## CPU更新の軽量エフェクトを使う

標準Forward描画で火花や煙を追加する場合は、初期化済みの`app`へCPU更新の発生装置を登録します。更新と描画は`WebgApp.start()`の通常のフレーム処理へ任せます。

```js
const cpuSparks = await app.createParticleEmitter({
  name: "cpu-sparks", maxParticles: 320,
  useShadow: true, groundY: -7.5, preset: "spark", seed: 31
});
cpuSparks.emit(24, {
  position: [0, 0, 0], positionSpread: [0.3, 0.3, 0.3],
  velocity: [0, 12, 0], velocitySpread: [8, 4, 8],
  gravity: [0, -18, 0], drag: 0.06,
  life: 0.9, lifeSpread: 0.2, size: 1.6, sizeSpread: 0.5,
  color: [1, 0.85, 0.4, 1], colorSpread: [0, 0.08, 0.1, 0],
  shadowAlpha: 0.55, shadowScale: 1.1, shadowY: -7.5
});
```

CPU版は`life`と`lifeSpread`、Compute版は`lifetime: [min, max]`で寿命を指定します。CPU版の`preset`は`spark`、`smoke`、`debris`、`pickup`のテクスチャ表現を選び、`setPreset()`で変更できます。影用ビルボードの`shadowY`は床の高さにそろえます。発生条件をCPUから追いたい小規模な表現に適しています。

`samples/compute_particle_emitter/index.html`では、SceneYAMLによる連続発生、一括発生、停止、消去、Bloom切替、容量拒否を操作できます。`samples/circular_breaker2/index.html`では、衝突位置と方向から火花を発生させる使い方を確認できます。

## 行動のイベントから粒子を発生させる

`samples/fantasy/scene.js`では、足元・魔法・被弾の装置を宣言しています。
`appearance.colors`は二つのHDRのRGB配列を渡します。
単色にする場合も、同じRGB配列を二つ指定します。RGBAにはしません。

`main.js`の`move()`と`attack()`が行動の位置から粒子を発生させ、
`reset()`が装置の`clear()`で前の戦闘の粒子を消します。
更新とPBRへの合成は`WebgSceneApp`に任せ、独自の`step()`を追加しません。
ゲームへ組み込む順序と再開始・解放の対応は、
`PBRシーンから小さなゲームへ.md`と`samples/fantasy/README.md`を参照してください。
