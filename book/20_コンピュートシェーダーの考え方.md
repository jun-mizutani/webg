# コンピュートシェーダーの考え方

粒子の位置、画像の明るさ、多数の物体の速度などは、同じ計算を多くの要素へ繰り返し適用します。コンピュートシェーダーは、このような計算をGPU（Graphics Processing Unit：画像処理装置）上で並列に実行する仕組みです。本章では、配列と画像の小さな例から、処理する要素、実行する数、結果を渡す先を考えます。

ここで学ぶのは計算の組み立て方です。21章で`ComputePass`と描画を接続し、22章でCPUとのデータ交換、同期、性能を詳しく確認します。

## この章の読み方

### この章を読む前に必要な知識

JavaScriptの配列と、18章のWGSL（WebGPU Shading Language：WebGPU用シェーディング言語）の基本を確認してください。

### 初回に読む範囲

要素ごとの計算、ディスパッチとワークグループ、ストレージバッファとストレージテクスチャ、描画へ結果を渡す順序を読んでください。

### 必要になったときに読む範囲

21章では具体的なリソース作成と実行コード、22章ではメモリ配置、読み戻し、競合への対処を参照します。画面効果は34〜36章、標準粒子は26章、物理は27〜28章へ進みます。

### この章を終えた時点でできること

並列計算に適した更新を見分け、要素数に合わせた実行数と、計算結果を置くリソースを選ぶ考え方を説明できます。

## 一つの要素へ一つの計算を割り当てる

1000個の粒子を動かす場合、各粒子の現在位置へ「速度×経過時間」を足します。入力が同じ時刻の位置と速度なら、粒子ごとの結果を独立して計算できます。このような処理では、各実行へ配列のインデックスを割り当てます。

次のWGSLは、配列の値を2倍にする計算部分です。`values`をストレージバッファへ接続した状態を想定した部分例で、JavaScript側のバッファ生成と接続は22章で説明します。

```wgsl
@group(0) @binding(0)
var<storage, read_write> values: array<f32>;

@compute @workgroup_size(64)
fn main(@builtin(global_invocation_id) id: vec3<u32>) {
  // 各実行が担当する配列要素を選び、実際の要素数を確認する
  let index = id.x;
  if (index >= arrayLength(&values)) {
    return;
  }
  values[index] = values[index] * 2.0;
}
```

`global_invocation_id`はGPUが実行へ割り当てる番号です。配列ではそのX成分をインデックスとして使います。1000要素なら、0番から999番が更新対象です。各実行が別の要素へ書くことで、同じ場所への同時書き込みを避けられます。

粒子同士の衝突のように他の要素を読む計算では、入力と出力を分けると、全要素が同じ時刻の状態から次の状態を求められます。二組のバッファを交互に使うピンポン方式や同期は22章で扱います。

## ディスパッチと実行数

ディスパッチは、GPUへ計算を実行するよう指示する操作です。実行はワークグループというまとまりで数えます。上の`@workgroup_size(64)`は、1グループに64実行を含める指定です。

1000要素では、`Math.ceil(1000 / 64)`により16グループを実行します。合計1024実行になるため、最後の24実行は配列の範囲を確認して終了します。コード内の範囲確認は、要素数が64の倍数から変わった場合にも必要です。

画像では幅と高さを使う二次元のグループを選べます。例えば1グループを8×8実行にし、幅を8で割って切り上げたグループ数と、高さを8で割って切り上げたグループ数を指定します。各実行は担当する画素座標が画像内かを確認してから処理します。

## 配列と画像の保存先を選ぶ

ストレージバッファは、位置、速度、寿命、数値配列などの構造化データを保存するGPUリソースです。ストレージテクスチャは、座標で読み書きする画像の保存先です。作る結果が配列か画像かを先に決めると、接続するリソースを選びやすくなります。

画面処理では、入力画像から色を読み、出力画像へ加工した色を書きます。粒子では、入力の位置・速度から次の位置・速度を作り、描画処理がその値を参照します。結果をそのまま次のGPU処理へ渡せる用途では、CPUへの読み戻しを減らせます。

## 更新してから描画へ渡す

アプリケーションの中心は、これまでと同じ`WebgApp`です。粒子や物理の状態更新を描画の前へ、画像加工をシーン描画の後へ接続します。

```text
粒子・物理: 状態の更新 → 更新後の状態でシーンを描画 → 表示
画面効果:   シーンを画像へ描画 → 画像を加工 → 表示
```

JavaScriptからの記録順、描画との接続、画像の形式は21章で具体的に確認します。結果を調べるための読み戻しと、共有メモリを使う同期は22章で扱います。まずは「何を入力にし、何を更新し、どこへ渡すか」を一続きの処理として説明できるようにしましょう。

## まとめ

コンピュート処理は、多数の要素へ計算を割り当て、要素数に合わせてグループを実行し、結果をGPUリソースへ保存します。次の21章では、この考え方を`ComputePass`、画像、描画処理へ接続します。
