# NEON COASTER — フォローカメラで走るジェットコースター

NEON COASTERは、夜の立体コースを4両編成の車両が自動走行し、`EyeRig`の追従視点で先頭車両を追い続けるデモです。閉じたCatmull–Rom曲線からレール、枕木、支柱、車両姿勢を生成し、上昇、降下、旋回、バンクを一周の流れとして見せます。最後尾が通過した後方では制御点を少しずつ動かしてコース形状を変え、次の周回では車両も更新後のレールを走ります。コース外周の3列に並ぶ72棟のビルは、横幅、奥行き、高さに基準寸法から±2〜4mの変化を加えた輪郭と、白からクリーム、琥珀色、オレンジへ移る窓明かりで夜の街並みを作ります。金属レール、車両、発光ガイド、都市照明、速度粒子をPBR画面へまとめ、カメラとコースの動きから速度感を確認できます。

## 実行と操作

[neon_coaster.html](neon_coaster.html) をWebGPU対応ブラウザで開きます。車両は読み込み完了後に`TURBO ON`の183 km/hで自動走行を始めます。`TURBO`を押すと通常の118 km/hと切り替わり、`PAUSE`は車両移動と新しい速度粒子の発生を一時停止します。`MUSIC`は175 BPMの`run_neon`を開始・停止します。音声は利用者がボタンを押した後に始まり、全体音量は40%、BGM音量は34%です。

追従カメラの視野角は70°で、標準設定より広い範囲を見渡せます。Canvas上のドラッグで視点に角度を加え、ホイールで車両との距離を6〜33の範囲で変えられます。遠ざかるとコースを広く見渡せます。画面上部には現在の速度、高さ、バンク角を表示します。Canvasはウィンドウの大きさに合わせて更新されます。

## 利用するwebgの機能

`CoasterApp`は`WebgSceneApp`を継承し、標準のPBRシーン構築へFollow型`EyeRig`と複数の色付きDeferred Lightingを接続します。カメラ階層は先頭車両へ取り付け、車両のローカル前方3.5を注視します。カメラ位置は車両後方へ12、上方へ2.6離し、コースのバンク姿勢を上方向の基準へ利用します。短辺基準の視野角を70°にし、追従姿勢は応答値18、最大角速度720度/秒で補間されます。

レールのねじれは、曲線の進行方向を軸に横・上方向を回転させるバンクとして作ります。周回位置`t`に応じた細かい4周期の波`sin(8πt)×8°`と、緩やかな1周期の波`sin(2πt+0.7)×13°`を合成し、係数45/21を掛けて理論上±45°以内に収めます。この角度をレール断面、枕木、車両へ共有し、車両のバンクをFollowカメラの上方向にも使います。波は周回位置から求めるため、傾きの変化をコース全体へ演出として配置します。

レールと発光ガイドは`Shape`で曲線に沿うチューブを生成し、枕木、車両、遠景灯は共有ジオメトリのインスタンスとして配置します。中央の発光ガイドは全周を等しい4区間に分け、緑、オレンジ、青、白の順に発光させます。元の9点曲線を12点へ再標本化し、12スパンを12個の描画チャンクに分けます。12個の制御点で、広い区間にわたる滑らかな曲線の変化を作ります。Catmull–Romの1制御点は前後4スパンに影響するため、最後尾がスパンbへ入る時に2点後ろの制御点P[b−2]を動かします。この点が変える4スパン（b−4〜b−1）はすべて通過済みです。制御点は1スパンごとに更新されます。目標位置は初期位置から横方向最大±3.0、高さ方向最大±1.8の範囲で選び、0.82秒かけて滑らかに移動します。影響を受ける4チャンクのレール3本と支柱形状を再生成し、枕木の配置姿勢を更新します。車両も同じ制御点列から位置と姿勢を求めるため、次の周回では更新後のレールに沿って走ります。

先頭車両は赤、後続車両は弱い自己発光を持つ暗い青の金属材質とし、暗い区間でも編成を見分けられるようにしています。4両すべての上面を、車体端より少し内側を通る細い銀色のチューブ状手すりで四辺から囲みます。水平材の中心は車体上面から約0.14の高さにあり、低い枠として見えます。柱側面は青灰色の高金属度・低roughness材質で、色付き照明をシャープな反射として映します。床は金属反射を抑えた暗い青灰色で、夜景を保ちながら面の輪郭がわずかに見える明るさです。PBR材質、環境光、6灯の点光源、方向光のシャドウマップ、SSR、Bloomを組み合わせ、金属の反射と発光を表現します。SSAOと被写界深度は停止し、動くレールの輪郭、反射、発光へ描画の焦点を合わせています。

SceneYAMLは描画設定と標準`ComputeParticleEmitter`を定義します。走行中は先頭車両の左右外側から、赤から橙色の粒子を約0.045秒ごとに発生させます。左右それぞれの発生数は約1.4秒周期で2〜16個に変わり、火花の密度に波を作ります。粒子は左右方向から後方へ45度傾いた向きに、1.05〜3.75の速度で広がり、0.2〜0.55秒で消えます。Compute Shaderで位置、速度、寿命を更新します。`GameAudioSynth`は内蔵譜面からBGMを合成します。

## 確認ポイント

先頭車両、レール、進行方向が同じ画面に入り、登りと下りでカメラが滑らかに追従することを確認します。旋回では車両とカメラがコースのバンクを共有し、ドラッグによる角度変更後も先頭方向の追跡が続きます。走行を続けると最後尾の後方で制御点が移動し、該当するレール、枕木、支柱が滑らかに更新されます。次周に車両が更新後の区間を通り、`PAUSE`中は制御点と形状が停止して再開後に動き出すことを確認します。起動時は`TURBO ON`の183 km/hで、押すと118 km/hの通常走行へ切り替わります。先頭車両を含む4両の低い手すりと、左右の火花が周期的に濃く・薄くなる様子も確認できます。

夜景ではシアン、赤紫、緑、オレンジの4色が巡回する都市の柱上面、シアンと赤紫を中心とする遠景灯、金属レールのハイライト、車両後方の速度粒子を見比べられます。SSRは画面内の情報を利用するため、反射の見え方はカメラ位置と画面端に応じて変わります。

## 実装を読む

`scene.yaml`が描画と粒子設定、`track.js`が曲線評価、区間ごとの形状再生成、車両配置を担当します。`CoasterApp.js`が追従カメラと照明、`main.js`が走行更新、HUD、操作、音楽、終了処理を担当します。`style.css`は全画面表示と画面幅に応じたHUD配置を定義します。サンプル固有の拡張はこのフォルダ内へまとめ、webgコアの公開モジュールをそのまま利用します。
