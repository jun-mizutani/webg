# Karakuri Maker／Karakuri Player

Makerでは「置く → ためす → なおす」を同じ画面で繰り返せます。子どもにも使いやすい操作で、部品を並べて仕掛けの動きを試せます。

`karakuri_maker.html`でSceneYAMLを編集し、`karakuri_player.html`で同じSceneYAMLを動かすサンプルです。つみき、球、坂、6枚のカラフルなドミノ、ゴール、PBR材質、static／kinematic／dynamicの物理設定を一つの作品データへまとめる構成を確認できます。

## 使い方

1. `http://localhost:8000/samples/karakuri/`を開く
2. `つくる`を開き、下の「ぶひん」からボール、坂、つみき、ドミノ、ゴールを選ぶ
3. 画面の置きたい場所を押す。選んだ部品がそこへ現れる
4. 立体を押すとオレンジ色になる。つかんで上下左右へ動かし、`↶ ひだり`／`↷ みぎ`で部品を傾ける
5. `もうひとつ`で同じ部品を増やし、`はずす`で片付ける
6. `ひとつ もどす`で直前の編集へ戻る
7. `ためす`で同じ画面で動きを確認する。試運転中は3Dビュー上部の`1.0`、`0.5`、`0.25`から速度倍率を選べる
8. `とめる`、`はじめから`、`なおす`で試運転を観察・再編集する
9. `おとなの設定`から作品をSceneYAMLまたはgzipで保存する。「しまう」を押した時点の配置は、このブラウザーで`初期配置に戻す`を使うときの配置として保存される
10. 保存した初期配置へ戻すときは、`おとなの設定`の`初期配置に戻す`を使う

Makerの「ためす」は現在の編集状態を同じ画面で実行します。Playerを通常URLで開いたときは、保存済みSceneYAMLよりリポジトリの標準SceneYAMLを優先して読み込みます。別のSceneYAMLを試す場合はPlayerの「ひらく」から明示的に読み込めます。

MakerはXY工作面で配置・移動します。部品のない場所をマウスでドラッグすると視点を回転でき、マウスを離すと約0.35秒で正面へ戻ります。戻っている途中にもう一度ドラッグすると、その時点の視点から操作を続けられます。部品の上で始めたドラッグは部品のXY移動になります。「ドミノ 6こ」を選んで画面を押すと、少し薄くした6色のドミノがまとまって現れます。既定のSceneYAMLには坂、ゴール、6枚のカラフルなドミノを配置しています。球と発射装置は明るいアルミ色で表示します。既定の発射台は半径`0.12 m`の球を最大5個まで同時に残し、試運転中に最大24個を2秒間隔で生成します。見た目の床は平らな床として表示し、物理用の水平平面と高さをそろえます。背面と左右の壁は床の範囲に合わせた大きさで、光の反射、影、接触陰影を見せる背景として残し、床と壁は工作部品として選べない表示にしています。「しまう」で保存した配置はブラウザー内へ保持されますが、MakerとPlayerの通常起動ではリポジトリの標準SceneYAMLを読み込みます。保存した配置へ戻すときは「初期配置に戻す」を使い、別のブラウザーや端末へ渡す場合は保存したSceneYAMLを「ひらく」から読み込みます。

球とドミノの物理設定には密度の項目はなく、質量と形状の大きさから運動を計算します。半径`0.12 m`の既定球は質量を約`19.54 kg`にして、体積から逆算した密度がアルミニウムの`2,700 kg/m³`程度になるようにしています。サイズ`[0.10, 0.6, 0.32] m`のドミノは体積から質量を`51.84 kg`として、球と同じ密度にしています。PBR材質の`metallic: 1.0`は金属らしい見た目を指定する値で、物理の密度を変更しません。Playerの通常起動ではリポジトリの標準SceneYAMLを読み込み、保存済みSceneYAMLは起動時の入力に使いません。

Playerでは、SceneYAMLに記録されたPBR、SSAO、SSR、弱いDoFを使って画面を作ります。エミッターの球はCompute physicsへ実行中に追加され、同時存在数を超えた球は一定時間後に回収されます。3Dビュー上部の速度倍率ボタンは`playback.timeScaleOptions`を表示し、重力や質量を変更せず、物理計算とアニメーションの時間倍率だけを変更します。StartまたはMakerの「ためす」を押すと音声を有効にし、球が床・壁・部品・ゴール板へ反発したときは短い接触音、ゴールへ届いたときは別の上昇音を鳴らします。ゴール表示後も試運転は続きます。

## SceneYAMLの交換

`karakuri_scene.yaml`はMakerとPlayerの間で交換するデータです。Procedural Textureはpreset名、必要な`tile`差分、appearanceを共有し、生成された画像ファイルは共有しません。例えば床は`wood.oak.mixed-sawn`を使い、`tile.joint.widthMeters: 0`で板境界の幅を指定します。壁は`ceramic.white.square`を使い、床と壁の両方へ`scale: 2`を指定します。`scale: 2`はテクスチャの一周期を2倍に広げ、同じ面上の反復を半分にします。Procedural Textureを使うBoxは`Primitive.mapRealCuboid()`で実寸UVを作り、MakerとPlayerは既存のProcedural Texture APIへ`scale`を渡してShape完成前に適用します。静的な床と壁はサンプル側で対象Shapeを作り直し、動的なBoxは生成時に同じ順序で適用するため、両方でテクスチャの大きさがそろいます。SceneYAMLを編集した場合は、Makerの`シーンを開く`で検証してからPlayerへ渡します。

## このサンプルの対応範囲

3Dメッシュ選択、XY配置・移動、回転、複製、取り外し、Undo、同じ画面での物理付き試運転、発射器、接触音、ゴール到達時の別効果音、接触に基づくゴール表示、保存・読込みを実装しています。ゴール表示後も物理は継続します。試運転では、ゴール到達時の表示とドミノの連鎖を確認します。
